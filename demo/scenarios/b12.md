# Scenario B12: one coordinator, many harnesses

Driver: `node demo/b12-harnesses.mjs [--agents a,b,c,w] [--sim-a] [--give-up] [--out DIR]`
(repo root, Node ≥ 22.18). Target: `demo/target-app` (the M1 auth/session service).

## Cast

| | harness | Weft adapter (declared level) | agent / task |
|---|---|---|---|
| A | Claude Code, `claude -p --output-format stream-json` | `adapters/claude-code` (L3) | `claude-a` / T-1 "Session expiry" (priority 1) |
| B | Codex CLI, `codex exec --json` + `exec resume` | `adapters/codex` (L2) | `codex-b` / T-2 "Signup endpoint" |
| C | OpenCode, `opencode serve` + `opencode run --attach` (`opencode/big-pickle`) | `adapters/opencode` (L3) | `opencode-c` / T-3 "Session refresh" |
| W | none: a scripted "human" edit, seen by the file watcher | `adapters/watcher` (L0) | `human-w` / T-4 "Health check" |

Every checkout is a git worktree of one fresh `origin`; each run gets a fresh coordinator repo on
the preview gateway and per-run tokens (never printed). Each agent's `join` record carries the
capabilities its adapter declared (`summary.json` → `declared_capabilities`).

## The collision

A changes `createSession(userId)` to `createSession(userId, opts: SessionOptions)`. B (signup)
and C (`refreshSession` in a new `src/auth/refresh.ts`) both start a session "the way login
does", i.e. the old way, and planned that in a first turn before A's change. The human writes
`src/ops/health.ts` calling `createSession("u_health")`. None of these diffs touch the same
lines: plain git would merge three type errors into main.

## Timeline

1. The watcher starts in W's checkout (hello, snapshot).
2. B and C read the code and reply with a plan (bases pinned, no edits).
3. A runs; once A's signature change is accepted in the log, the human writes the stale call
   and B and C implement in the same conversations (concurrently).
4. B's and C's stale edits must be **denied at edit time** (`stale_assumption` caused by A's
   event); each changes approach; their next edits are accepted.
5. The human's stale call is only **reported** (L0: the file is already written); `git commit`
   is refused by the pre-commit gate until the human fixes the call.
6. The driver commits every checkout through the git hooks (trailers), merges A, B, C, W into
   `main`, and runs `tsc -p .` and `node --test` on the merge.

`--give-up` replaces C's implement prompt with "if Weft blocks you, stop and reply BLOCKED":
the stop gate must then refuse (each refusal arrives as a new user turn in the OpenCode
session) up to the runaway guard.

## Pass criteria (`summary.json`)

| criterion | evidence |
|---|---|
| `a_finished` | Claude exit 0, `result.subtype == success` |
| `b_denied_at_edit_time_by_a`, `c_…` | a `rejected` check by the agent with an error `stale_assumption` whose `caused_by_seq` is A's event, and a `deny` in its hook log carrying it |
| `b_changed_approach`, `c_…` | accepted edits after the rejection, and the merged file calls `createSession` with a second argument |
| `w_l0_reported_and_commit_gated` | a rejected `human-w` edit caused by A's event, a refused first commit, an accepted edit after the fix, a successful second commit |
| `merged_cleanly`, `tests_green` | all merges without conflicts; `tsc` and `node --test` exit 0 on main |
| (`--give-up`) `c_stop_refused`, `c_refusal_started_new_turns` | Stop hook `block` records, each followed by a `[weft] Not done …` user turn and an assistant reply in `c-session-messages.json` |

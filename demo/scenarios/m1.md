# Scenario M1: two live agents, one function, conflict caught at edit time

Driver: `node demo/m1-collision.mjs [--runs N] [--first K] [--out DIR]` (repo root, Node ≥ 22.18).
Target: `demo/target-app` (auth/session service: users, sessions, JSON API routes, HTML pages,
node:test suites). Report: `demo/evidence/m1-report.md`, regenerated tables:
`node demo/m1-report.mjs --write`.

## Cast

| | agent A | agent B |
|---|---|---|
| harness | Claude Code 2.1.289, `claude -p --output-format stream-json` | Codex CLI 0.154, `codex exec --json` (+ `exec resume`) |
| Weft adapter | `packages/adapters/claude-code` (L3) | `packages/adapters/codex` |
| WCP agent / task | `claude-a` / T-1 "Session expiry" (priority 1) | `codex-b` / T-2 "Signup endpoint" (priority 0) |
| checkout | git worktree `agent-a` | git worktree `agent-b` |

Both checkouts are worktrees of one fresh `origin` repo, so neither agent sees the other's
edits on disk. Each run gets a fresh coordinator repo on the preview gateway
(`weft-gateway-preview`) and per-run tokens (scopes `agent`+`observe`, never printed).

## The collision

`src/auth/session.ts` starts with `createSession(userId: string): Session`, called by `login`
in `src/api/routes.ts`.

- **A (T-1)** makes sessions expire: `createSession(userId: string, opts: SessionOptions)`
  with `SessionOptions = { ttlMs: number }`, `expiresAt`, expiry in `getSession`; updates the
  login caller and `test/session.test.ts`. Touches `session.ts`, `routes.ts`, the session test.
- **B (T-2)** adds `POST /api/signup` to `accountRoutes` in `src/api/account.ts`: register the
  user, then start a session "the same way login does" — i.e. `createSession(user.id)` as B's
  checkout shows it — plus `test/signup.test.ts`. Touches `account.ts` and a new test file.

The two diffs never touch the same lines (git merges them cleanly either way), but B's call is
wrong after A's change: plain git would merge a type error into main.

## Timeline (one run)

1. **B turn 1** (`codex exec`): read the code and reply with a plan, no edits. B's SessionStart
   hook says hello; its `base_seq` is pinned to what the conversation has seen.
2. As soon as B's `join` is in the log, **A** (`claude -p`) starts — A and B run at the same time.
3. When A's signature change of `createSession` is *accepted* in the log, and B's planning turn
   has ended, **B turn 2** (`codex exec resume <thread>`, same conversation) is told to
   implement. B still believes the old signature.
4. B's first edit adding `createSession(user.id)` must be **denied at PreToolUse** with a
   positioned `stale_assumption` error that cites A's event and quotes A's diff.
5. B changes approach (passes `{ ttlMs }`), its next edit is accepted; both agents finish.
6. The driver commits both checkouts through the installed git hooks (Change-Id/Task-Id/
   Agent-Id trailers), merges `agent-a` then `agent-b` into `main`, and runs `tsc -p .` and
   `node --test "test/**/*.test.ts"` on the merge.

## Pass criteria (all must hold; computed by the driver into `summary.json`)

| criterion | evidence |
|---|---|
| B received an edit-time diagnostic caused by A's event | a `rejected` `check` event by `codex-b` with an `error` `stale_assumption` whose `caused_by_seq` is A's signature event, and a PreToolUse `deny` in B's hook log carrying it |
| B changed approach | an `accepted` `codex-b` edit after the rejection, and the merged `account.ts` calls `createSession` with a second argument |
| both finished | exit 0 for A and both B turns; Claude `result.subtype == success` |
| merge clean | `git merge` of both branches without conflicts |
| tests green | `tsc` and `node --test` exit 0 on the merged main |

A run whose Codex turn failed in the model backend (quota, budget) is marked `aborted` and not
counted.

## Metrics recorded per run

- Hook round-trip: every adapter hook process appends to `.weft/log/hooks.jsonl` its total time
  since node start (incl. boot), the hook logic time, and each coordinator HTTP call's time.
- Token overhead: characters of Weft text injected into the model (welcome, diagnostics, deny
  reasons; `WEFT_HOOK_TRACE=1` keeps the verbatim text), against the harness-reported model
  tokens of the run.

## Codex model backend

Default: the logged-in ChatGPT account. `WEFT_M1_CODEX_PROVIDER=openrouter` (with
`OPENROUTER_API_KEY`) runs the same Codex CLI, hooks and adapter against OpenRouter's
Responses API (`openai/gpt-6-sol` unless `WEFT_M1_CODEX_MODEL`). With a model Codex has no
catalog metadata for, Codex offers no native `apply_patch` tool: the model calls
`apply_patch <<'PATCH'` through the shell, Codex intercepts and applies it, the hooks see
`tool_name: "Bash"`, and no PostToolUse fires. The adapter handles both paths.

## Integration bugs found and fixed (on wt/m1)

1. **Codex hooks never fired. The installer wrote the wrong file, in the wrong place.**
   - B5 wrote `.codex/settings.local.json`, which Codex does not read. Codex reads
     `.codex/hooks.json` (or `[hooks]` in config.toml).
   - For a linked git worktree, Codex loads the project layer from the **main** worktree, not
     the linked one. Verified with codex-cli 0.154: a SessionStart hook in
     `origin/.codex/hooks.json` fired for a session in `agent-b`; the worktree's own file did
     not.
   - The installer now writes `.codex/hooks.json` in the checkout and, for linked worktrees,
     also in the main worktree. The hook command is checkout-agnostic: each hook resolves its
     checkout's `.weft/codex.json` from the hook's `cwd` and does nothing in checkouts without
     one, such as the Claude worktree.
2. **Codex registered no lifecycle hooks, so R2 could never fire for Codex.**
   - Only PreToolUse/PostToolUse `apply_patch` were installed, so the first `hello` happened
     at B's first edit with `base = head`, past A's signature change.
   - The installer now registers SessionStart, UserPromptSubmit, PreToolUse
     (`apply_patch`, `Bash`), PostToolUse (`apply_patch`, `Bash`), Stop, and SessionEnd
     (3 s cap).
   - Verified live: SessionStart, UserPromptSubmit, Stop and SessionEnd all fire under
     `codex exec`. `codex exec resume` keeps the same hook `session_id` (= thread id), so the
     base pinned in turn 1 survives into turn 2.
3. **Codex pre-edit checks ignored `Update File` patches,** which is how agents edit existing
   files.
   - The B5 parser only handled Add/Delete.
   - `packages/adapters/codex/src/edits.ts` now parses the whole apply_patch grammar
     (Add/Delete/Update/Move, `@@` headers, `*** End of File`, multi-file). It applies update
     chunks the way Codex does (exact, then trailing-whitespace-insensitive, then
     whitespace-insensitive sequence search).
   - The check submits all files of a patch as one event; the commit does the same.
4. **apply_patch through the shell was invisible.**
   - With a model Codex has no catalog metadata for (every OpenRouter model), Codex offers no
     native apply_patch tool. The model runs `apply_patch <<'PATCH' … PATCH` in the shell, and
     Codex intercepts and applies it.
   - The hooks see `tool_name: "Bash"`, and **no PostToolUse fires** for it (verified).
   - The adapter now recognises shell apply_patch (heredoc and argv forms, `applypatch`, a
     leading `cd X &&`) and routes it through the same check. Pending pre-edits whose
     PostToolUse never arrives are committed from disk at the next hook, so the coordinator
     still gets B's edit (run 1: `no PostToolUse for call_…; committing its edit from disk` →
     #10).
5. **Two adapters in two worktrees of one repo overwrote each other's git hooks.**
   - `rev-parse --git-path hooks` is the shared common dir, so the Codex install replaced the
     Claude `commit-msg`/`pre-commit`.
   - Both installers now give a linked worktree its own hooks dir via worktree-scoped
     `core.hooksPath` (`extensions.worktreeConfig`).
6. **Hook timing and injected-text accounting (both adapters).**
   - Every hook process appends `{event, tool, total_ms, handle_ms, calls[{op, ms}],
     decision, injected_chars, weft_chars}` to `.weft/log/hooks.jsonl`.
   - `WEFT_HOOK_TRACE=1` also keeps the verbatim injected text.

  - A welcome line per session: 544 chars, twice for B because turn 2 is a new WCP session.

  - Nothing else: the scenario has no warnings or inbox noise.
- **Overhead: about 0.07–0.08% of B's model tokens.** Text injected once stays in context, so

  rejected check, and the next edit was accepted. Cutting the quote would trade tokens for
  retries.

## Findings for the design

- **Codex is L3-capable on the hooks it actually fires**: SessionStart, UserPromptSubmit,
  PreToolUse (apply_patch and Bash), PostToolUse (native apply_patch and Bash), Stop,
  SessionEnd. The adapter still declares L2 because the Stop-gate *refusal* path was not
  exercised live in M1. The next ChatGPT-backed run, or a stop-gate variant, should confirm it
  before raising the level.
- **Shell-applied patches have no PostToolUse in Codex.** Any Codex adapter must treat
  "pending pre-edit + file changed on disk" as the commit trigger. Agents that write files
  with `printf`/`sed` (seen with a local model) are still uncoordinated: that is the L0
  watcher's job, and an argument to run it alongside every Codex session.
- **Worktree layout matters for harness config discovery.** Sandboxes (B7) clone per agent, so
  they are unaffected. Local multi-agent setups that use `git worktree` hit both the Codex
  project-layer issue and the shared git-hooks issue.
- Reaffirms B4's v0.2 proposal: the coordinator could attach the causing hunk to
  `stale_assumption`. Both adapters now fetch and quote it themselves, and the quote is
  load-bearing for a one-shot reroute.
